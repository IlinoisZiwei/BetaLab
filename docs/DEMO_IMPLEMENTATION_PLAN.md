# BetaLab 两周 Demo 实施计划

## 1. 目标与范围

周期：10 个工作日。三人并行开发，最后两天用于修复、部署和演练。

目标：支持 3–5 人同时使用，完成以下真实流程：

登录／注册 → 选择预置场馆和路线 → 上传视频 → 查看分析和带时间点的 suggestions → 提交个性化视频生成 → 浏览其他内容 → 收到站内通知 → 查看生成结果 → 公开分享、浏览和评论。

部署方式：默认同 Wi-Fi，通过本地机器的局域网地址访问；异地展示时开启免费临时隧道。应用、数据库、视频和算法计算均保存在本地。服务机器需要持续开机联网。

算法已基本可用，但仍需调整。本计划为算法调整保留时间，不把算法接入视为已经完成。

### 必须完成

- 用户名密码注册、登录、退出和预设测试账号；个人身材资料。
- 预置场馆和路线；用户选择路线后上传一分钟以内的视频。
- 数据持久保存，重启后账号、视频、评论和任务记录保留。
- 视频默认私有；公开后所有已登录用户可查看和评论；改回私有后收回其他用户访问权限。
- 私有视频的缩略图、分析和生成结果继承权限，后端验证文件访问权限。
- 分析与生成采用后台任务；用户可以离开页面，重新登录后查看状态和结果。
- 生成完成后站内通知，支持未读标记和跳转结果。
- suggestions 时间点可跳转到对应视频位置。
- Community、My Library 和评论接入真实数据。
- 提供本地部署、备份恢复及可选临时隧道操作说明。

### 本次暂缓

邮箱验证、邮件找回密码、浏览器关闭后的系统推送、用户创建场馆路线、云端部署、自动扩容。登录入口做基本限流；演示注册可按配置关闭。

## 2. 分工与工作量

| 人员 | 主要责任 | 明确边界 |
| --- | --- | --- |
| A：账号、视频与部署 | 后端基础、数据库迁移规范、鉴权、个人资料、场馆路线、视频上传和权限、存储、部署与备份 | 提供公共鉴权和存储接口；不承担所有模块的 API 和联调 |
| B：前端与社区 | 前端整体接入、Community、My Library、评论前后端、任务和通知界面、结果与 suggestions 展示 | 负责请求和显示；对应 API 或算法错误由模块负责人修复 |
| C：算法、任务与通知 | 算法调整和适配、任务 API、worker、排队和重试、结果入库、通知后端 | 负责完整计算链路；通知创建、查询和已读 API 由 C 实现 |

工作量控制：C 在第 3–8 天每天预留约三分之一时间用于算法调整与结果检查。算法基础设施先采用简单持久化队列和单计算 worker，不在 Demo 阶段建设复杂调度系统。

A 制定数据库和鉴权规范；B、C 分别编写自己模块的迁移和 API。每个人完成自己的检查、接口文档和修复。B 主导现有集中式前端页面的修改，A、C 优先提交独立后端模块，减少同文件冲突。

## 3. 技术框架与接口约定

- 前端：复用 React、TypeScript、Vite。
- API：FastAPI；数据库：PostgreSQL，使用版本化迁移。
- 存储：本地持久目录；数据库记录存储标识，通过统一存储接口读写，避免业务逻辑依赖绝对路径。
- 任务：数据库持久化队列、独立 Python worker；初期一个计算任务运行，其余排队。任务领取需保证不会被重复执行。
- 部署：应用和数据库优先通过 Docker Compose 管理。算法按依赖情况在容器或宿主机运行，C 提供可重复安装和启动说明。
- 通知：前端定期轮询任务与通知，页面不可见时降低频率；任务结束停止该任务轮询。
- 未来扩展：API、worker、数据库和文件存储边界独立，便于迁往云服务器、对象存储及增加 worker。

### 第 2 天前必须确定的接口

| 接口／约定 | 主责 | 对接方 |
| --- | --- | --- |
| 登录会话、当前用户和统一错误格式 | A | B、C |
| 视频上传、归属、可见性和受保护文件访问 | A | B、C |
| 评论列表、创建和本人删除 | B | A 提供鉴权 |
| 分析／生成任务创建、状态、重试和结果 | C | A 提供存储，B 展示 |
| 通知列表、未读数和已读操作 | C | B 展示 |
| 算法输入输出和结果格式 | C | A、B |

算法输入包含任务 ID、视频标识、路线信息、所需用户参数和算法必需素材；具体字段由 C 确认。输出包含 suggestions、以秒计的时间点及其对应视频、生成产物、算法版本和错误信息。分析与生成作为独立任务类型。

状态统一为排队中、运行中、成功、失败；不显示虚构进度百分比。结果完整落盘后才标记成功；任务结束与通知创建保证一致，避免漏通知或重复通知。

## 4. 分阶段实施

### 阶段一：接口和项目骨架（第 1–2 天）

| 人员 | 任务 | 交付 |
| --- | --- | --- |
| A | 建立 API、数据库、迁移和配置框架；定义用户、资料、场馆、路线、视频；提供鉴权和存储约定 | 可启动后端、数据库迁移初版、公共接口说明 |
| B | 盘点页面和原型数据；建立 API 请求模块、登录状态、路由保护；定义评论结构和 API | 页面接入清单、请求模块、评论接口说明 |
| C | 确认算法依赖和运行方式；梳理仍需调整的问题；定义任务、结果、通知结构和 API；提供模拟执行器 | 算法接入说明、调整清单、示例输入输出 |

共同验收：接口格式明确，三人可独立开发；模拟结果明确标注，不能混作真实算法结果。确认展示机器的系统、资源、可用磁盘和算法运行环境。

### 阶段二：核心模块并行实现（第 3–4 天）

| 人员 | 任务 | 交付 |
| --- | --- | --- |
| A | 注册登录、密码哈希、个人资料；预置路线；上传和持久存储；视频列表详情及可见性；时长和大小校验 | 可用的账号与视频 API |
| B | 接入登录、路线、上传、My Library；实现评论 API 和页面；接 Community 真实数据 | 两个用户可分享和评论 |
| C | 任务表和 API、单 worker、排队和失败重试；通知 API；包装真实算法入口；开展必要算法调整 | 模拟任务闭环、真实算法可被独立调用 |

共同验收：两个账号分别上传；公开内容可查看评论，私有内容及文件不可被他人访问；重启后数据保留；任务可查询、失败可重试。

### 阶段三：后台生成与通知闭环（第 5–6 天）

| 人员 | 任务 | 交付 |
| --- | --- | --- |
| A | 完善结果存储、鉴权播放、缩略图、视频范围请求；补足前端所需视频接口 | 原视频和产物均可按权限播放 |
| B | 任务状态、通知列表、未读标记和结果跳转；My Library 展示运行中和完成任务 | 用户离开任务页面仍可找到结果 |
| C | 接入真实算法、结果保存、通知创建；处理重复提交、中断和错误日志；继续算法调整 | 后台真实生成闭环 |

共同验收：提交 Generate → 浏览其他视频 → 收到通知 → 打开结果。用户关闭浏览器不影响任务；重启服务后中断任务标记明确并可重试，不永久停留在运行中。

### 阶段四：真实数据与权限联调（第 7–8 天）

| 人员 | 任务 | 交付 |
| --- | --- | --- |
| A | 检查访问权限、上传异常、删除与文件生命周期；准备局域网配置 | 稳定的数据和媒体访问 |
| B | 展示真实 suggestions 和生成结果；完善时间跳转、手机布局和异常提示 | 完整前端流程 |
| C | 核对分析结果、时间点、编码格式和真实耗时；完成展示必需的算法调整 | 浏览器可播放、时间点正确的真实结果 |

共同验收：至少一组真实分析和一组真实生成结果从应用内提交并展示。检查重复点击同一时间点、媒体未加载、时间超出长度、任务重复提交、公开改私有和算法失败。

第 8 天结束冻结展示功能。尚未完成的非核心算法优化记录为已知问题，不挤占最后两天部署和演练时间；影响核心正确性的问题仍需修复。

### 阶段五：部署和多人演练（第 9–10 天）

| 人员 | 任务 | 交付 |
| --- | --- | --- |
| A | 启停脚本、环境变量模板、迁移和备份恢复；局域网入口；可选免费临时隧道 | 部署和恢复文档 |
| B | 预设账号、展示内容、操作说明；不同手机和浏览器检查 | 展示脚本和可用页面 |
| C | 确认展示机器算法环境；预生成真实示例结果；检查排队和中断处理 | 算法启动说明、真实备用结果 |

共同验收：3–5 人同时登录、浏览、上传和评论；多个计算任务正确排队；通知归属正确；数据重启不丢；同 Wi-Fi 访问正常；异地展示需要时验证隧道下登录、上传和播放。

预先完成的真实结果用于辅助展示，需标明来源；现场新任务展示实际排队和运行状态，不承诺未经测量的完成时间。

## 5. 进度检查和工作量调整

| 时间点 | 检查内容 | 调整方式 |
| --- | --- | --- |
| 第 2 天 | 接口是否明确，算法调整是否影响输入输出 | 优先冻结接口；必要时由适配层兼容算法变化 |
| 第 5 天 | C 的算法调整是否挤占任务框架；A、B 是否出现接口等待 | 若 C 超负荷，A 接手任务领取与状态基础实现；B 接手预置数据脚本和展示文档，分担 A |
| 第 8 天 | 核心流程是否全部可演示 | 暂缓非核心优化，最后两天聚焦修复和演练 |

每天约 15 分钟同步已完成项、接口变化、阻塞和下一步。按功能分支提交 PR；鉴权、迁移、任务领取和重试由另一人复核。每人负责本模块检查，跨模块问题联合定位，不能默认归给前端负责人。

## 6. 最终交付清单

- 可运行的前端、API、数据库迁移、worker 和算法适配层。
- 预设账号、场馆路线、公开和私有示例视频。
- 真实分析结果、可点击时间点、真实生成结果和站内通知。
- 本地部署及可选临时隧道说明，无密钥的配置示例。
- 数据库和视频文件的备份恢复步骤；任务日志与错误排查说明。
- 3–5 人演练记录、实际算法耗时和已知问题清单。

验收原则：真实数据、真实权限、持久化和后台任务必须成立；算法性能限制如实呈现，为后续增加算力与云端部署保留接口。
