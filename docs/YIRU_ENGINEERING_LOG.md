## 2026-11-15：本地多用户 Demo 当前实现与验证

### 本轮已落地

- 项目提供 Docker Compose PostgreSQL、版本化迁移与可重复执行的 Gym／route／bundled 媒体种子数据。迁移覆盖场馆路线、用户与会话、用户上传视频、视频标题、存储后端标识和 `share_as_beta`。
- FastAPI 提供用户名密码注册／登录／退出、HttpOnly Cookie 会话、CSRF 与精确 Origin 校验、资料读写、场馆／路线查询、用户视频上传／查询／受保护播放／修改可见性／删除。用户视频元数据在 PostgreSQL，媒体文件写入 `UPLOAD_DIR` 私有本地目录；支持 MP4/MOV，服务端用 ffprobe 校验，限制 90 秒和 200 MiB。
- 前端已强制登录并连接 API；注册后可填写或跳过身高、臂展，资料保存后下次登录恢复。场馆与路线来自数据库。
- 上传流程可从设备选择视频，填写自定义标题与可选描述，选择 Private／Public；选择 Public 时可另选是否 Share as beta。上传视频进入 My Library，并关联所选 gym／route。真实上传视频的可见性和 Beta 分享可在视频管理中修改。
- Community 普通列表展示所有数据库中的 Public 用户视频（是否 Beta 不影响普通 Community）；Community Beta 只展示 Public 且 `share_as_beta=true` 的视频。Beta 列表展示上传者身高、臂展及与当前用户可计算的差值；身体数据只在用户选择 Beta 分享时通过公开列表接口返回。
- 预置 sample attempts 也显示在普通 Community，明确标注为 Preset sample，来源仍是仓库 bundled 路线视频，不作为用户上传记录或数据库权限对象。
- 普通 Community 先展示视频列表，点开后进入全屏纵向视频浏览。详情显示标题和可展开描述，进入可视区域时尝试带声音播放，点按可播放／暂停；浏览器可能要求用户先点播放。视频详情和其他应用页面均支持左滑返回；桌面端可拖动左滑。
- My Library 的 attempts 按 gym → route → video 分组；上传视频缩略图取自视频首帧。Community Beta 的公开视频卡和个人资料差值已接通。
- 本机局域网展示可在 Vite 用 `--host 0.0.0.0 --port 5174` 监听，并在本地 `.env` 的 `APP_ORIGINS` 加入当前浏览器 origin；API 保持 `127.0.0.1:8788`，浏览器通过 Vite 同源代理访问。手机和电脑可同时通过同一 Wi-Fi 使用同一服务，各自登录。局域网 IP 可能因网络变化而改变，`.env` 不提交。

### 本轮验证与当前机器

- `npm run build` 通过；`python3 -m py_compile backend/app.py` 和 `git diff --check` 通过。
- 本地 FastAPI 已重启以读取 Origin 配置，`/api/health` 返回 200。用户视频和账号数据属于本机数据库，不会随 GitHub push 上传。
- 构建仍打印 Vite 配置对 `__dirname` 和 JSON import 属性的兼容性提示，不影响当前构建。

- Community 点赞／收藏、评论的前端交互还没有对应的持久化 API；重启或换设备后的同步尚未接通。
- 持久任务队列、后台视频生成进度和完成通知尚未完成；现有算法预览接入不等于已交付完整后台任务系统。算法 worker 与上传处理的完整接入仍由算法协作者继续负责。

- 手机访问还受 Wi-Fi 客户端隔离、Mac 防火墙、Mac 休眠和本机网络变化影响；异地访问仍需后续配置隧道／公网入口。

## 2026-11-15：本地 Demo 的账号、视频和共享模型

### 已确认的 Demo 目标

- 先支持同一 Wi-Fi 下 3–5 人使用；需要异地展示时，通过免费临时隧道访问同一台本地服务。
- 应用服务、PostgreSQL、上传视频和算法任务均在本地机器运行；服务机器需要开机并保持网络连接。
- 注册使用用户名和密码。注册后可填写身高、臂展，也可跳过；下次登录从数据库恢复已保存资料。
- 场馆和路线由团队预置，路线及示例媒体可在后续持续导入。
- 上传视频上限为 90 秒；格式和文件大小限制由上传实现具体校验并向用户说明。
- 视频默认私有。上传者可将视频设为公开；公开视频可被同一 BetaLab 服务中的其他已登录用户查看和评论。改回私有后，其他用户的后续请求应立即被拒绝。
- 后台生成采用持久任务、排队和站内通知；算法由独立模块接入，当前算法基本可用但预留调整时间。

### 本地数据与权限模型

- 用户上传的视频文件保存在服务机器上的私有目录，不放在 `public/` 静态资源目录，也不提交 GitHub。
- PostgreSQL 保存账号、密码哈希、个人资料、路线、视频元数据、上传者、路线关联、可见性、文件存储标识、评论、任务状态和通知。数据库保存文件的逻辑存储标识，不把视频二进制塞进数据库。
- 文件由后端提供访问。每次读取都根据当前会话和数据库中的可见性判断权限；私有视频只允许上传者访问，公开视频允许该服务的登录用户访问。
- “本地”指服务端数据保存在运行服务的电脑，并不等于只允许这台电脑前的用户访问。Lisa 和 Yesyes 若访问同一服务，可以按 Private／Public 规则共享；若各自在自己的电脑启动独立服务和数据库，则数据彼此隔离。
- GitHub 保存代码与文档，不负责用户数据、上传内容或数据库备份。不要提交 `.env`、密码、会话 token、用户视频或本地数据库卷。
- 本地磁盘不是备份。Demo 应提供 PostgreSQL 与视频目录分别备份和恢复的步骤。

### 当前工程进度（记录本日志时）

- 前端使用 React、TypeScript、Vite。
- 本地 PostgreSQL 使用 Docker Compose；开发期间数据库容器在 `127.0.0.1:5433` 监听，Docker Desktop 需保持运行。
- FastAPI API 使用独立本地端口 `8788`；现有算法预览服务使用 `8787`，Vite 开发服务器为 `5174`。后续通过同源 `/api` 代理访问对应后端。
- 数据库初始目录包含 Gym A、Gym B，以及前端已有的 r1 Corner Study、r2 Long Reach、r3 Old Slab；r3 为归档路线。示例媒体记录与 `public/media` 中现有素材对应，示例媒体与用户上传分开。
- 已实现第一批 API：注册、登录、退出、Cookie 会话、个人资料、gym 和 route 查询。前端已接入账号、资料与场馆路线；未登录强制进入登录／注册页。
- 用户视频上传、媒体权限 API、评论持久化、任务队列和通知仍待后续实现；当前已有界面中的演示行为不能当作这些功能已完成。
- 任务细分和验收项见 [两周 Demo 实施计划](DEMO_IMPLEMENTATION_PLAN.md)；账号 API 页面手工验证方式见 [第一批 API 验证说明](ACCOUNT_API_VERIFICATION.md)。

### 后续正式上线的迁移方向

- 保留用户、路线、权限和评论等业务数据模型；数据库迁移至托管 PostgreSQL。
- 将本地文件存储替换为对象存储，通过存储适配接口切换；私有资源继续由鉴权后的后端或短时签名链接提供，公开状态继续由应用权限规则决定。
- API 与算法 worker 部署到云端机器；根据算法算力、任务量扩展 worker。
- 更新 Cookie 安全、域名、HTTPS、隧道／网络入口、限流、日志、监控、备份保留与恢复流程。
- 正式上线前补齐注册保护、账号恢复、删除政策、隐私说明和数据保留策略。
